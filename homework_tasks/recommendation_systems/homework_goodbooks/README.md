# Рекомендательная система книг Goodbooks-10k

## Описание проекта

Проект посвящен исследованию и сравнению алгоритмов рекомендаций книг на датасете
`Goodbooks-10k`.

**Цель проекта:**

Реализовать несколько подходов к формированию рекомендаций, оценить их
качество на общей тестовой выборке и предложить стратегию гибридизации для решения
проблемы холодного старта.

В работе рассматриваются четыре алгоритма:

- `Popularity Baseline` -> рекомендации по среднему рейтингу книг с минимальным порогом
  количества оценок
- `Content-Based Filtering` -> поиск похожих книг и персональные рекомендации по
  TF-IDF-профилям названий и тегов
- `Item-Based Collaborative Filtering` -> рекомендации по косинусной близости векторов
  пользовательских оценок
- `SVD` -> матричная факторизация на основе скрытых факторов пользователей и книг

## Описание данных

Используется открытый датасет `Goodbooks-10k` ->
`https://www.kaggle.com/datasets/zygmunt/goodbooks-10k`

Исходные таблицы находятся в директории `data/raw/`:

- `ratings.csv` -> оценки книг пользователями (`user_id`, `book_id`, `rating`)
- `books.csv` -> метаданные книг (идентификаторы, названия, авторы и рейтинговая
  статистика)
- `tags.csv` -> справочник пользовательских тегов
- `book_tags.csv` -> связи книг с тегами и частоты использования тегов
- `to_read.csv` -> книги, отмеченные пользователями для последующего чтения

В исходном файле `ratings.csv` содержится `981 756` записей. После объединения
повторяющихся пар (`user_id`, `book_id`) получено `979 478` уникальных взаимодействий.

Для моделирования использованы `53 424` пользователя и `10 000` книг.

Особенности идентификаторов:

- `ratings.book_id` соответствует `books.id`
- `book_tags.goodreads_book_id` соответствует `books.book_id`

Для устранения дубликатов пользовательские оценки одной книги агрегированы по среднему
значению. Затем взаимодействия разделены на обучающую и тестовую выборки отдельно для
каждого пользователя с сохранением не менее одной оценки в train.

Подготовленные файлы сохранены в `data/processed/`:

- `train_ratings.csv` -> `788 503` взаимодействия для обучения
- `test_ratings.csv` -> `190 975` взаимодействий для оценки

Разбиение воспроизводимо при `RANDOM_STATE = 42`.
Временные метки оценок отсутствуют, поэтому временное разделение данных не применялось.

## Этапы работы

### 1. Знакомство с данными и EDA

Основной ноутбук -> `notebooks/01_eda.ipynb`.

На этапе EDA выполнено:

- изучены размеры таблиц, пропущенные значения и дубликаты
- проанализировано распределение оценок и смещение в сторону высоких рейтингов
- исследована активность пользователей и количество оценок на книгу
- построены графики популярности и пользовательской активности
- определены распространенные теги книг
- исследована разреженность матрицы взаимодействий

Основные ограничения данных -> высокая разреженность (более `99,8%`), короткая история
значительной части пользователей и неполнота наблюдаемых оценок.

### 2. Базовые и контентные модели (Popularity Baseline и Content-Based Filtering)

Основной ноутбук -> `notebooks/02_baseline_content_based.ipynb`.

Реализовано:

- очистка повторяющихся оценок и воспроизводимое разбиение train/test
- рейтинг книг по средней обучающей оценке с порогом `20` оценок
- исключение ранее оцененных книг из персональной выдачи Popularity
- текстовые профили книг на основе названий и наиболее частых содержательных тегов
- фильтрация основных служебных тегов и ограничение до `20` тегов на книгу
- TF-IDF векторизация и косинусная близость
- функция `get_similar_books()` для поиска тематически похожих книг

В результате построена TF-IDF матрица размерностью `10 000 x 5 812`.
При пороге 20 оценок в рейтинге Popularity осталось `9 997` книг.

### 3. Коллаборативная фильтрация (Item-Based Collaborative Filtering)

Основной ноутбук -> `notebooks/03_collaborative_filtering.ipynb`.

Реализовано:

- разреженная матрица пользователь–книга размерностью `53 424 x 10 000`
- расчет косинусной близости книг по обучающим пользовательским оценкам
- предсказание рейтинга на основе взвешенного среднего оценок похожих книг
- функция `predict_item_rating()`
- функция `get_item_recommendations()` для формирования Top-N
- диагностика недостаточного числа похожих книг и параметр `min_positive_neighbors`
- предварительная оценка времени формирования рекомендаций

Разреженность обучающей матрицы составляет `99,8524%`.
Для итогового сравнения используется `top_k=10` и `min_positive_neighbors=3`.

### 4. Матричные разложения (Matrix Factorization) -> SVD

Основной ноутбук -> `notebooks/04_svd.ipynb`.

Реализовано:

- обучение модели `SVD` из библиотеки `scikit-surprise`
- `50` скрытых факторов и `20` эпох обучения
- прогноз оценок через `predict_svd_rating()`
- персональные Top-N рекомендации через `get_svd_recommendations()`
- исключение ранее оцененных книг
- анализ глобального среднего, пользовательских смещений, смещений книг и скрытых
  факторов
- расчет RMSE на всей отложенной тестовой выборке

Получены матрицы факторов пользователей `53 424 x 50` и книг `10 000 x 50`.

На всей отложенной тестовой выборке из `190 975` оценок рассчитана ошибка предсказания
**RMSE = `0.8416`**. Тестовые оценки не использовались при обучении модели.
RMSE характеризует точность числовых прогнозов, в отличие от метрик качества Top-N
рекомендаций.

### 5. Оценка и сравнение моделей

Основной ноутбук -> `notebooks/05_evaluation.ipynb`.

Для общего сравнения реализованы персональные Content-Based рекомендации и метрики:

- `Precision@5` -> доля известных релевантных книг в пяти позициях выдачи
- `Recall@5` -> доля найденных среди всех известных релевантных книг пользователя
- `nDCG@5` -> качество ранжирования с учетом позиций релевантных книг

Релевантной считается книга с тестовой оценкой `rating >= 4`.

Оценка проведена на фиксированной подвыборке из `200` пользователей, имеющих не менее
одной релевантной книги в test.
Все алгоритмы используют один набор пользователей и не
получают их тестовые оценки при формировании рекомендаций.

## Результаты сравнения моделей

| Модель                      | Precision@5 |   Recall@5 |     nDCG@5 |
|-----------------------------|------------:|-----------:|-----------:|
| Popularity Baseline         |      0.0000 |     0.0000 |     0.0000 |
| **Content-Based Filtering** |  **0.0430** | **0.1034** | **0.0861** |
| Item-Based CF               |      0.0030 |     0.0105 |     0.0052 |
| SVD                         |      0.0010 |     0.0010 |     0.0007 |

Дополнительные результаты:

| Модель                  | Пользователей с попаданиями | Пользователей без рекомендаций | Пользователей с полным Top-5 |
|-------------------------|----------------------------:|-------------------------------:|-----------------------------:|
| Popularity Baseline     |                           0 |                              0 |                          200 |
| Content-Based Filtering |                          36 |                              9 |                          191 |
| Item-Based CF           |                           3 |                             44 |                          156 |
| SVD                     |                           1 |                              0 |                          200 |

В рамках проведенного offline-эксперимента лучшие значения всех трех метрик показал
`Content-Based Filtering`.

Результат относится к выбранным пользователям, зафиксированным конфигурациям и имеющимся
тестовым взаимодействиям. Отсутствие книги среди тестовых оценок пользователя не
означает, что она ему не понравилась бы.

### 6. Гибридизация и выводы

Основной ноутбук -> `notebooks/06_hybrid_conclusions.ipynb`.

Предложена стратегия борьбы с холодным стартом:

- для новых пользователей -> Popularity Baseline
- для пользователей с положительной историей оценок -> Content-Based Filtering
- для новых книг с текстовыми характеристиками -> контентные рекомендации после
  подготовки их профилей
- для известных книг и пользователей -> дополнительные сигналы SVD
- при нехватке персональных рекомендаций -> заполнение свободных позиций Popularity
  Baseline

Гибридный алгоритм **предложен и обоснован**, но не реализован и не оценен отдельно.
Его потенциальные преимущества требуют экспериментального подтверждения.

## Ограничения исследования

- Тестовые оценки охватывают только часть возможных предпочтений пользователей.
- Большинство пар пользователь–книга не имеют наблюдаемых взаимодействий.
- Разбиение train/test не учитывает временной порядок оценок.
- Пользовательские теги получены из общего каталога без временных меток, поэтому их
  историческая доступность относительно test не подтверждена.
- Гиперпараметры моделей не подбирались на отдельной валидационной выборке.
- Выборка для итогового сравнения ограничена 200 пользователями.

## Запуск проекта

Команды выполняются из **корневой директории репозитория**, содержащей `pyproject.toml`.
Проектные импорты используют абсолютный путь
`homework_tasks.recommendation_systems.homework_goodbooks`.

### Установка зависимостей

```bash
poetry install
```

Убедитесь, что в Poetry-окружении установлены `scikit-surprise`, `scikit-learn`,
`scipy`, `pandas`, `numpy` и Jupyter, а также зависимости визуализации.

### Запуск Jupyter Notebook

```bash
poetry run jupyter notebook
```

Для воспроизведения работы откройте ноутбуки в следующем порядке:

1. `01_eda.ipynb` -> исследование исходных данных
2. `02_baseline_content_based.ipynb` -> очистка данных, train/test и базовые алгоритмы
3. `03_collaborative_filtering.ipynb` -> Item-Based CF
4. `04_svd.ipynb` -> матричная факторизация SVD
5. `05_evaluation.ipynb` -> оценка моделей
6. `06_hybrid_conclusions.ipynb` -> гибридная стратегия и итоговые выводы

Второй ноутбук сохраняет подготовленные `train_ratings.csv` и `test_ratings.csv` в
`data/processed/`. Для запуска следующих этапов эти файлы должны существовать.

Ноутбуки исследовательские: обучение моделей и расчеты выполняются в ячейках, отдельный
CLI для обучения и запуска рекомендательного API не предусмотрен.

## Итоговый вывод

В ходе проекта выполнен полный цикл учебного исследования рекомендательных алгоритмов:
от анализа качества данных и построения базовых моделей до персональных рекомендаций и
сравнения их по единому протоколу.

Наилучшие показатели Precision@5, Recall@5 и nDCG@5 в проведенном эксперименте получила
модель `Content-Based Filtering`, использующая текстовые признаки книг и историю
положительных оценок пользователя.

Для решения проблемы холодного старта предложено сочетание Popularity Baseline,
Content-Based и SVD. Реализация и оценка гибридной стратегии, а также расширение
методики валидации рассматриваются как дальнейшие направления работы.
