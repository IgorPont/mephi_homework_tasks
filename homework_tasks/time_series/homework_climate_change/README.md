# Прогнозирование среднемесячной температуры

## Описание проекта

Проект выполнен в рамках домашнего задания по дисциплине "Временные ряды".

Проект посвящен исследованию и прогнозированию временного ряда среднемесячных температур
на основе открытого датасета `Climate Change: Earth Surface Temperature Data`.

**Цель проекта:**

Реализовать базовый пайплайн прогнозирования временного ряда, включающий подготовку
данных, хронологическое разбиение, формирование скользящих окон, генерацию лаговых и
календарных признаков, обучение модели и оценку качества прогнозирования.

В качестве объекта исследования выбран временной ряд среднемесячных температур
Республики Беларусь (`Belarus`).

В работе рассматриваются два подхода к прогнозированию:

- `Linear Regression` -> линейная регрессия на основе лаговых и календарных признаков
- `Seasonal Naive Baseline` -> базовый сезонный алгоритм, использующий фактическую
  температуру аналогичного месяца предыдущего года

Особое внимание уделяется сохранению временной структуры наблюдений, обработке
пропущенных значений и предотвращению утечек данных (`Data Leakage`).

## Описание данных

https://www.kaggle.com/datasets/berkeleyearth/climate-change-earth-surface-temperature-data

в директории `data/raw/`.

Исходный датасет содержит `577 462` наблюдения,
`4` столбца и `243` уникальных значения `Country`.

После фильтрации данных по выбранной стране сформирован временной ряд из `3 239`
среднемесячных наблюдений за период с ноября 1743 года по сентябрь 2013 года.

В исходном временном ряду выявлено `73` пропущенных значения (`2,25%`).

Подготовленный временной ряд содержит `3 131` наблюдение продолжительностью около

### 2. Хронологическое разделение на обучающую и тестовую выборки (Holdout)

Реализована функция `split_temperature_series()` для хронологического разбиения
временного ряда.

Используется пропорция `80/20` без перемешивания наблюдений:

- первые `80%` наблюдений -> обучающая выборка (`train`)
- последние `20%` наблюдений -> тестовая выборка (`test`)

Результаты разбиения:

| Характеристика        |      Train |       Test |
|-----------------------|-----------:|-----------:|
| Начало периода        | 1752-10-01 | 1961-06-01 |
| Конец периода         | 1961-05-01 | 2013-08-01 |
| Количество наблюдений |      2 504 |        627 |
| Доля наблюдений       |     79,97% |     20,03% |
| Пропущенных значений  |          0 |          0 |
| Частота               |         MS |         MS |

Граница Holdout-разбиения соответствует `1961-06-01`.

Выполнены проверки:

- отсутствия пересечений между выборками
- сохранения хронологического порядка наблюдений
- непрерывности календарного диапазона
- сохранения регулярной месячной частоты
- полного восстановления исходного подготовленного ряда при объединении выборок

Построены графики общего Holdout-разбиения и детализации границы между обучающей
и тестовой выборками.

### 3. Разбиение методом скользящего окна (Rolling Window)

Реализована функция-генератор `generate_rolling_splits()` для формирования
последовательных временных разбиений с фиксированным размером обучающего окна.

Параметры Rolling Window:

| Параметр                 |    Значение |
|--------------------------|------------:|
| Размер обучающего окна   | 120 месяцев |
| Горизонт прогнозирования |  12 месяцев |
| Шаг смещения окна        |  12 месяцев |

Скользящие окна формируются исключительно на обучающей выборке,
полученной при Holdout-разбиении.

На `2 504` обучающих наблюдениях сформировано `198` полных скользящих разбиений.

Границы первых двух разбиений:

| Разбиение | Train start | Train end  | Validation start | Validation end |
|-----------|-------------|------------|------------------|----------------|
| Split 1   | 1752-10-01  | 1762-09-01 | 1762-10-01       | 1763-09-01     |
| Split 2   | 1753-10-01  | 1763-09-01 | 1763-10-01       | 1764-09-01     |

Последнее валидационное окно заканчивается в сентябре 1960 года.

Оставшиеся `8` месяцев обучающей выборки не образуют полного следующего разбиения,
однако используются при обучении итоговой модели.

Выполнены проверки корректности всех сформированных разбиений.

Построены графики первых двух разбиений и структуры первых пяти скользящих окон.

Rolling Window реализован как механизм формирования временных разбиений.
Обучение и оценка модели на каждом скользящем окне
в рамках текущего исследования не выполнялись.

### 4. Генерация признаков (Feature Engineering)

Реализована функция `build_temperature_features()` для преобразования одномерного
временного ряда в набор данных для обучения модели машинного обучения.

Сформированы следующие признаки:

| Признак     | Описание                                         |
|-------------|--------------------------------------------------|
| `lag_1`     | Температура предыдущего календарного месяца      |
| `lag_12`    | Температура аналогичного месяца предыдущего года |
| `month`     | Порядковый номер календарного месяца (`1–12`)    |
| `is_winter` | Индикатор зимнего сезона                         |

Индикатор `is_winter` принимает значение `1` для декабря, января и февраля,
для остальных месяцев `0`.

Целевая переменная -> `AverageTemperature`.

Для формирования лагов используется метод `shift()` библиотеки `pandas`.

Первые `12` наблюдений исключены из результирующего набора данных,
так как отсутствует необходимая история для формирования всех лаговых признаков.

Генерация признаков выполняется на непрерывной истории наблюдений с сохранением ранее
определенной границы Holdout-разбиения.

В результате сформированы следующие наборы данных:

| Набор     | Размерность |
|-----------|------------:|
| `X_train` |   2 492 x 4 |
| `y_train` |       2 492 |
| `X_test`  |     627 x 4 |
| `y_test`  |         627 |

Все тестовые наблюдения сохранены.

Выполнены проверки:

- корректности лаговых и календарных признаков
- соответствия лагов фактическим историческим температурам
- отсутствия пропущенных и бесконечных значений
- сохранения границ Holdout-разбиения
- отсутствия текущих и будущих значений целевой переменной среди входных признаков

### 5. Обучение модели и прогнозирование

В качестве основной прогнозной модели используется `LinearRegression`
из библиотеки `scikit-learn`.

Модель обучена на `2 492` наблюдениях с использованием четырех лаговых
и календарных признаков.

Коэффициенты модели определяются методом наименьших квадратов (`Ordinary Least Squares`,
OLS).

Получены следующие коэффициенты:

| Признак     | Коэффициент |
|-------------|------------:|
| `lag_1`     |    0.295293 |
| `lag_12`    |    0.661570 |
| `month`     |   -0.290655 |
| `is_winter` |   -2.038237 |

Свободный член модели составляет `2.646775`.

При прочих равных условиях модель демонстрирует более высокую чувствительность к
изменению годового лага, чем месячного.

Данный результат согласуется с выявленной выраженной годовой сезонностью температур.

Для получения прогнозов используется протокол `One-Step-Ahead Forecasting`:

- модель обучается исключительно на обучающей выборке
- прогнозирование выполняется на один календарный месяц вперед
- при прогнозировании используются доступные фактические температуры предыдущих месяцев
- параметры модели в течение тестового периода не обновляются
- текущие и будущие значения температуры не используются в качестве входных признаков

Предшествующие фактические наблюдения тестового периода становятся доступными для
формирования последующих одношаговых прогнозов.

Полученные результаты не являются единым многошаговым прогнозом на весь тестовый период.

Масштабирование признаков и подбор гиперпараметров не выполнялись.

Сформировано `627` прогнозов для всех тестовых наблюдений за период
с июня 1961 года по август 2013 года.

Построены графики:

- коэффициентов линейной регрессии
- фактических и прогнозных температур за весь тестовый период
- детализации первых трех годовых циклов
- диаграммы рассеяния фактических и прогнозных значений

### 6. Оценка качества прогнозирования

Реализована функция `calculate_forecast_metrics()` для расчета следующих метрик:

- `MAE` (`Mean Absolute Error`) -> средняя абсолютная ошибка
- `RMSE` (`Root Mean Squared Error`) -> корень из средней квадратичной ошибки
- `MAPE` (`Mean Absolute Percentage Error`) -> средняя абсолютная процентная ошибка

Метрики MAE и RMSE выражаются в градусах Цельсия, MAPE в процентах.

Для дополнительного сравнения используется базовый сезонный алгоритм
`Seasonal Naive Baseline`.

В качестве прогноза базового алгоритма используется фактическая температура аналогичного
месяца предыдущего года (`lag_12`).

Оба подхода оцениваются на одной тестовой выборке из `627` наблюдений
и в рамках одинакового протокола доступности исторических данных.

Дополнительно выполнено:

- сравнение качества линейной регрессии и Seasonal Naive
- исследование применимости MAPE
- независимая проверка расчета всех трех метрик
- анализ описательных статистик остатков
- исследование распределения ошибок прогнозирования
- анализ динамики скользящей MAE
- исследование качества прогнозирования по календарным месяцам
- сравнение ошибок прогнозирования зимой и летом

### Особенности интерпретации MAPE

В тестовой выборке:

- `180` наблюдений содержат отрицательные температуры
- нулевые фактические температуры отсутствуют
- `55` наблюдений (`8,77%`) имеют абсолютное значение температуры менее `1 гр. Цельсия`
- минимальное абсолютное значение температуры составляет `0,004 гр. Цельсия`

Высокие значения MAPE обусловлены чувствительностью данной метрики к
близким к нулю фактическим значениям.

Дополнительным ограничением является отсутствие естественного абсолютного нуля в шкале
Цельсия.

Поэтому для интерпретации качества прогнозирования в качестве основных метрик
используются MAE и RMSE.

MAPE рассчитано в соответствии с требованиями домашнего задания.

## Запуск проекта

Команды выполняются из **корневой директории репозитория**, содержащей `pyproject.toml`.

Проектные импорты используют абсолютный путь
`homework_tasks.time_series.homework_climate_change`.

### Подготовка исходных данных

Необходимо загрузить датасет `Climate Change: Earth Surface Temperature Data`
с Kaggle и разместить файл `GlobalLandTemperaturesByCountry.csv` в директории:

```text
homework_tasks/time_series/homework_climate_change/data/raw/
```

Для выполнения исследования остальные файлы исходного датасета не требуются.

### Установка зависимостей

```bash
poetry install
```

Убедитесь, что в Poetry-окружении установлены `pandas`, `numpy`, `scikit-learn`,
`matplotlib`, `jinja2` и Jupyter.

### Запуск Jupyter Notebook

Из корневой директории репозитория выполните:

```bash
poetry run jupyter notebook
```

Корневая директория репозитория должна быть доступна в путях поиска Python-модулей для
корректной работы абсолютных импортов.

Для воспроизведения исследования откройте:

```text
homework_tasks/time_series/homework_climate_change/notebooks/01_climate_forecasting.ipynb
```

Выполните перезапуск Jupyter Kernel и последовательное выполнение всех ячеек
(`Restart Kernel and Run All`).

Ноутбук содержит все этапы исследования:

1. Подготовка данных и исследование временного ряда.
2. Хронологическое Holdout-разбиение.
3. Формирование скользящих окон (Rolling Window).
4. Генерация лаговых и календарных признаков.
5. Обучение модели и прогнозирование.
6. Оценка качества прогнозирования.
7. Итоговые выводы.

Предварительное формирование промежуточных файлов не требуется.

Ноутбук исследовательский: подготовка данных, обучение модели, прогнозирование и оценка
качества выполняются непосредственно в ячейках. Отдельный CLI или сервис прогнозирования
не предусмотрен.

## Результирующие файлы

- `notebooks/01_climate_forecasting.ipynb` -> полный цикл исследования, исходный код

  воспроизведения

В сохраненных результатах последовательного выполнения ячеек ошибки отсутствуют.

Обученная модель, промежуточные наборы данных и прогнозы отдельно на диск не
сохраняются.

## Итоговый вывод

В ходе проекта реализован полный цикл учебного исследования временного ряда
среднемесячных температур, от анализа и подготовки исходных данных до обучения
прогнозной модели и оценки качества прогнозирования.

Особое внимание уделено сохранению регулярной месячной структуры наблюдений, корректной
обработке пропусков, хронологическому разбиению и предотвращению утечек данных.

Эксперимент показал, что базовая модель линейной регрессии с лаговыми и календарными
признаками способна учитывать выраженную годовую сезонность температур и обеспечивать
снижение ошибок относительно простого сезонного алгоритма.

На отложенной тестовой выборке получены следующие результаты:

- **MAE = 2.0319 гр. Цельсия**
- **RMSE = 2.7079 гр. Цельсия**
- **MAPE = 228.2554%**

По сравнению с Seasonal Naive Baseline достигнуто снижение MAE на `9,51%`
и RMSE на `9,78%`.

Дополнительный анализ выявил выраженную сезонную зависимость качества прогнозирования,
ошибки зимних прогнозов более чем в два раза превышают ошибки летних прогнозов.

Возможные направления дальнейшего развития включают циклическое кодирование календарных
признаков, учет долгосрочного температурного тренда, исследование статистических и
нелинейных моделей, оценку качества на скользящих окнах и многошаговое прогнозирование.

Цель проекта достигнута, поставленные задачи выполнены.
